# EvalHub Agent Benchmark Roadmap

路线图以评测对象的演进为主线，并借鉴本地 EvalScope 的 Agent 评测分层：普通 Benchmark 可切换到 Native AgentLoop；复杂 Benchmark 通过 Adapter 自带工具、环境和评分协议；最后通过 External Agent Bridge 评测完整 Agent CLI。FastAPI、队列、数据库等平台能力服务于这条主线，不再单独作为阶段目标。

## Phase 1：单轮 LLM 补全基线（当前）

目标：稳定运行 `Prompt → Answer → Score` 的基础评测闭环。

- GSM8K、MMLU 等问答型 Dataset
- Model Adapter 与同步 Evaluation Runner
- Exact Match Evaluator
- 样本级结果、失败样例与 JSON Report
- CLI 和本地 Web 控制台

验收标准：给定模型、Dataset 和 Benchmark，可以复现单轮补全结果与聚合分数。

## Phase 2：Native AgentLoop

目标：不重写 Dataset 和 Evaluator，只通过 Agent 配置把现有 Benchmark 切换为多轮工具评测。

- 类型化 `NativeAgentConfig`：Strategy、Tools、Environment、Max Steps
- 结构化 Message、Tool Call、Model Output 与 Stop Reason
- `generate → parse → tool call → observation` 循环
- Strategy、Tool、Environment 注册机制
- 工具错误转换为 Observation，允许 Agent 修正和重试
- 每条样本产生统一 `AgentTrace`，记录生成、工具、错误和提交事件

验收标准：同一个 GSM8K 类 Benchmark 在不修改 Evaluator 的情况下，可以由配置切换为多轮工具评测，并在结果中保存完整 Trace。

## Phase 3：Agent Benchmark Adapter

目标：支持由 Benchmark 自己定义专属循环、工具、样本级环境和最终结果提取方式。

- `AgentBenchmarkAdapter` 构建默认 Strategy、Tools、Environment 和初始消息
- Benchmark 默认值优先，运行配置只覆盖允许调整的字段
- 每样本创建、重置并关闭 Local/Docker Sandbox
- 支持 Function Calling、GAIA、SWE-bench、BFCL 类任务协议
- 支持从环境提取补丁、文件或数据库状态等最终制品
- 以官方规则或最终环境状态判分，Trace 指标作为辅助诊断

验收标准：至少一个环境型 Benchmark 可以从干净状态重复运行，验证最终环境结果，并区分模型、工具和环境失败。

## Phase 4：External Agent Bridge

目标：不修改外部 Agent 源码，直接评测 Codex、Claude Code 等完整 Agent CLI。

当前进展：已用固定 Codex CLI 壳、可替换 Ollama 基模和 Coding Mini v2 完成最小闭环。内置题集
包含简单、中等、困难各 2 道，支持过程回放、最终工作区隐藏校验、失败归因和分档报告；其他 Agent
CLI、公开外部 Benchmark 和多租户隔离仍未实现。

- `AgentRunner` 协议和 Runner 注册机制
- External Agent CLI 的安装、启动、超时和资源回收
- 模型请求协议转发、Trial 鉴权和流式事件处理
- Native 与 External 共用 `AgentTrace`、结果与评分结构
- 同一 Benchmark 比较不同 Agent，或比较同一 Agent 的不同底层模型
- 在统一 Trace 上增加成功率、成本、时延、稳定性和回归门禁

验收标准：一个外部 Agent CLI 可以完成样本执行、原 Benchmark 评分和 Trace 回放，且无需修改该 Agent 的源码。
