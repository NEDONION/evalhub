## LocalEvaluationTask

`LocalEvaluationTask` 是本地控制台的持久化执行记录，存于 `.runtime/evalhub.db`。它与领域层 `EvaluationJob` 共享任务 ID 和状态语义，但额外承载 API 请求、实时进度、资源遥测与完整结果，避免把本地调度细节放入领域实体。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 与最终报告一致的任务 ID |
| request_json | json | 数据集、adapter、模型、地址、采样模式和数量 |
| status | enum | pending/running/success/failed/canceled |
| completed_samples | int | 已形成样本级结果的数量 |
| total_samples | int | 实际加载的样本总数 |
| created_at | datetime | 创建时间，UTC |
| updated_at | datetime | 最近状态或采样更新时间，UTC |
| started_at | datetime? | Worker 实际开始时间，UTC |
| finished_at | datetime? | 终态时间，UTC |
| error_message | string? | 失败或中断原因 |
| cpu_percent | float | Ollama 任务为本机当前 CPU；其他执行器为评测进程树 CPU |
| peak_cpu_percent | float | 与当前 CPU 相同口径的任务生命周期峰值 |
| memory_bytes | int | 评测进程树当前 RSS 字节数 |
| peak_memory_bytes | int | 任务生命周期 RSS 峰值 |
| gpu_supported | bool | 当前平台是否提供可靠 Apple AGX 或 NVIDIA GPU 指标 |
| gpu_percent | float? | 当前活动设备利用率 |
| peak_gpu_percent | float? | 任务窗口内设备利用率峰值 |
| gpu_memory_bytes | int? | 当前活动设备显存字节数 |
| peak_gpu_memory_bytes | int? | 任务窗口内显存峰值 |
| benchmark | string? | 成功结果的 Benchmark 名称摘要 |
| passed_samples | int? | 成功结果的通过样本数摘要 |
| average_score | float? | 成功结果的平均分摘要 |
| result_json | json? | 成功任务的完整 `EvaluationResult` |

任务列表查询只读取摘要列，不加载 `result_json`；详情查询才返回完整结果。`elapsed_seconds` 和 `progress.percent` 是 API 根据时间戳与计数派生的字段，不重复存储。

模型历史成绩同样直接读取上述摘要列，不新增冗余表。模型任务按 `benchmark:<dataset>` 或
`suite:<suite_id>` 形成可比范围，每个模型以范围内历史最高 `average_score` 排名；Agent 任务、
无分任务和其他范围不会进入聚合。一次成绩严格超过该模型在同范围内此前最高分时，派生为刷新纪录。

## EvaluationNode

模型任务创建时会同时生成持久化节点。节点保存稳定 `node_key`、类型、依赖、状态、尝试次数、
检查点、输出、错误、样本进度和累计耗时。状态为
`pending/running/success/failed/blocked/canceled`；成功节点在恢复和重试时不会重复执行。

## EvaluationNodeEvent

节点事件是追加式审计记录，保存事件类型、时间、尝试次数、消息和结构化 payload。状态变化、
自动重试、人工重试和服务恢复都会产生事件，旧事件不覆盖。

## EvaluationSampleCheckpoint

Benchmark 节点按 `node_id + sample_id` 保存样本状态、输入摘要、结果或错误和尝试次数。
`status=failed` 可以表示已经完成评分但答案未通过，是否需要恢复执行由 `result_json` 是否存在
独立判断。节点恢复时只执行尚未形成评分结果的样本；API 仍可用失败状态分页读取 bad case，
避免一次加载完整数据集结果。
