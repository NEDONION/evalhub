# EvalHub API Draft

本文同时记录当前本地 HTTP 服务已经实现的接口，以及后续 FastAPI 层的资源化草案。当前接口统一使用 JSON；错误响应为 `{"ok": false, "error": "可诊断信息"}`。

## 当前本地控制台 API

### 服务与资产状态

```http
GET /api/health
GET /api/datasets
GET /api/ollama/status?model=qwen2.5%3A0.5b&base_url=http%3A%2F%2F127.0.0.1%3A11434
```

`GET /api/ollama/status` 的 `model_options` 同时包含本地已安装和推荐模型。每项提供：

- `installed`：是否已经存在于 Ollama。
- `size_bytes`：实际容量、推荐预估容量或 `null`。
- `size_kind`：`actual`、`estimated` 或 `unknown`。

### Ollama 模型下载

```http
POST /api/ollama/pulls
GET /api/ollama/pulls?model=qwen2.5%3A1.5b
DELETE /api/ollama/pulls?model=qwen2.5%3A1.5b
```

创建请求：

```json
{
  "model": "qwen2.5:1.5b",
  "base_url": "http://127.0.0.1:11434"
}
```

下载任务包含 `status`、`message`、`completed_bytes`、`total_bytes`、`speed_bytes_per_second`、`eta_seconds` 和 `error`。活动状态为 `pending`、`pulling`、`verifying`；终态为 `success`、`failed`、`canceled`。同一时间只执行一个实际下载，刷新页面后可以通过 GET 恢复任务快照。

安全约束：模型名称必须是合法 Ollama 标签，`base_url` 只接受无凭据的本机 HTTP 回环地址。

### Benchmark 数据集缓存

```http
POST /api/datasets/prepare
```

```json
{
  "dataset": "gsm8k",
  "force": true
}
```

`force=false` 复用已有缓存或首次下载；`force=true` 下载到临时候选位置，校验成功后原子替换现有缓存。响应包含 `operation`（`cached` 或 `updated`）和 `sample_count`。

### 异步评测任务

```http
GET /api/benchmarks
GET /api/suites
GET /api/model-performance?scope=benchmark:gsm8k
POST /api/evaluations
GET /api/evaluations
GET /api/evaluations/{task_id}
POST /api/evaluations/{task_id}/cancel
GET /api/evaluations/{task_id}/nodes/{node_id}
GET /api/evaluations/{task_id}/nodes/{node_id}/samples?status=failed&limit=50&cursor=...
POST /api/evaluations/{task_id}/nodes/{node_id}/retry
```

创建请求沿用评测表单字段：`dataset`、`adapter`、`model`、`base_url`、
`sample_mode`，并可附加 `subject`、`limit`、`evaluation_type` 和
`agent_framework`；Agent 评测额外使用 `agent_difficulty`，套件评测额外传入 Registry 中的稳定
`suite_id`。创建接口先写入 SQLite，
再以 `202` 返回排队任务，不等待模型执行完成。

Agent MVP 只接受固定组合 `evaluation_type=agent`、`agent_framework=codex`、
`dataset=coding_mini` 和 `adapter=ollama`：

```json
{
  "evaluation_type": "agent",
  "agent_framework": "codex",
  "dataset": "coding_mini",
  "adapter": "ollama",
  "model": "your-tool-capable-code-model",
  "base_url": "http://127.0.0.1:11434",
  "sample_mode": "all",
  "agent_difficulty": "medium"
}
```

`agent_difficulty` 可选值为 `all`、`easy`、`medium`、`hard`，省略时为 `all`；Agent 请求的
`sample_mode` 固定为 `all`，样本筛选只由难度字段决定。模型评测若携带 Agent 专属字段会返回
`400`，避免静默忽略错误配置。

成功结果在通用聚合字段之外包含 `agent`、`sample_results`、`capability_report` 和
`difficulty_report`。`benchmark_version` 标识当前题集版本，`requested_difficulty` 记录请求筛选；
每条 `sample_results` 及失败示例都包含 `difficulty` 和 `difficulty_reason`。
`capability_report.dimensions` 固定按规划、代码理解、实现、工具使用、验证、稳健性六项返回
`0..1` 分数，供控制台六边形图和文本列表共同展示。

新 Agent 任务会创建一个 `kind=agent_benchmark` 节点。节点详情中的 `events` 按自增 `id` 保持
追加顺序，并可能包含 `sample_started`、`agent_session_started`、`agent_turn_started`、`agent_message`、
`tool_started`、`tool_finished`、`workspace_changed`、`verifier_finished`、`sample_finished`
和 `runner_error`。事件只保存白名单字段和截断后的消息；不包含模型内部思维链或未知 JSONL。
其中隐藏校验只在 Agent 退出后产生。

`sample_results[].diagnostics.outcome` 用于解释零分或通过结果：

- `runtime_error`：Codex 缺失、超时、非零退出或没有最终消息。
- `no_action`：没有受控文件变化且隐藏校验失败。
- `wrong_solution`：存在受控文件变化，但隐藏校验失败。
- `passed`：最终工作区通过隐藏校验。

列表按创建时间倒序返回轻量摘要，包含：

- `status`：`pending`、`running`、`success`、`failed` 或 `canceled`。
- `progress`：已完成样本数、总样本数和百分比。
- `timing`：创建、开始、结束时间与总耗时。
- `resources`：任务进程树当前/峰值 CPU、内存，以及可选 NVIDIA GPU/显存。
- `result_summary`：成功任务的 Benchmark、总样本、通过样本和平均分；活动任务为 `null`。

详情接口额外返回原始 `request` 和完整 `result`。控制台只在用户选择任务后请求详情，
避免每秒轮询重复传输失败样例与原始 JSON。取消接口只接受活动任务；终态任务返回 `409`。

Benchmark 和 Suite Registry 会明确返回执行器就绪状态。任务详情同时包含工作流节点摘要；节点
详情按需返回检查点和审计事件，样本接口使用稳定游标分页，失败节点可通过重试接口重新入队。
控制台对活动任务每秒刷新一次任务详情，并随运行节点耗时变化读取最新事件，不使用 SSE 或
WebSocket。

模型结果的 `capability_profile` 固定包含知识、指令遵循、数学、综合推理、代码、安全可信六项。
单项 Benchmark 可以返回 `partial` 画像；未覆盖维度为 `unassessed` 且分数为 `null`，不会按
0 分计入聚合。套件中部分 Benchmark 被阻塞或失败时，成功节点仍可生成带覆盖率的部分画像。
版本化行业 Suite 不接受表单残留协议参数：其中 MMLU 固定运行全部官方学科。资产准备节点和
Benchmark 结果包含真实本地内容的 SHA-256，Registry 的 revision 字段只声明运行时摘要策略。

任务由单 Worker 按 FIFO 执行，历史记录保存在 `.runtime/evalhub.db`。同一数据库使用 OS 文件锁
限制为一个 Worker 进程。服务重启会恢复排队任务和模型任务的中断节点，并复用成功节点与样本
检查点；旧版无节点任务保持明确的中断失败语义。

`GET /api/model-performance` 只聚合已经产生有效分数的模型评测，Agent 任务不会进入模型榜单。
`scope` 使用 `benchmark:<dataset>` 或 `suite:<suite_id>`，不同范围严格隔离；不传时选择有效运行
次数最多的范围。响应包含可选 `scopes`、`selected_scope`、按历史最高分排序的 `models`，以及
最近一次严格超过同模型既有最好成绩的 `record`。每个模型同时提供最新分、最好分、运行次数和
按时间排列的轻量历史点，不返回完整结果正文或失败样本。

### 同步评测兼容接口

```http
POST /api/evaluations/run
```

请求包含 `dataset`、`adapter`、`model`、`base_url`、`sample_mode`，并可按数据集附加
`subject` 或自定义 `limit`。响应把聚合结果放在 `result` 字段下；该接口为现有调用方保留，
Web 控制台使用异步任务接口。

```http
GET /health
```

```http
POST /models
GET /models
GET /models/{model_id}
```

创建模型：

```json
{
  "name": "qwen-demo",
  "version": "v1.0",
  "type": "sft",
  "endpoint": "http://localhost:8001/v1/chat/completions"
}
```

```http
POST /datasets
GET /datasets
GET /datasets/{dataset_id}
```

## Benchmarks

```http
POST /benchmarks
GET /benchmarks
GET /benchmarks/{benchmark_id}
```

## Evaluation Jobs

```http
POST /evaluation-jobs
GET /evaluation-jobs
GET /evaluation-jobs/{job_id}
POST /evaluation-jobs/{job_id}/cancel
```

创建任务：

```json
{
  "model_id": "model_123",
  "benchmark_id": "benchmark_456",
  "runtime_config": {
    "temperature": 0,
    "max_tokens": 512
  }
}
```

```http
GET /evaluation-jobs/{job_id}/results
GET /evaluation-jobs/{job_id}/report
```
