# EvalHub 仓库级 AGENTS.md 设计

## 背景

EvalHub 是一个 Python 3.11 项目，采用 `src` 布局，以 pytest 和 Ruff 作为现有开发工具，
同时包含少量原生 HTML、CSS 和 JavaScript。仓库目前缺少面向编码 Agent 的统一规则文件，
需要通过根目录 `AGENTS.md` 明确工程边界、质量门槛和完成标准。

## 目标

- 在仓库根目录创建单一 `AGENTS.md`，覆盖整个仓库并以 Python 约束为核心。
- 使用与现有代码和 `pyproject.toml` 一致的命令、目录和工具，不引入额外依赖。
- 为功能开发、缺陷修复、测试、文档更新和最终交付提供可执行的检查清单。
- 保护密钥、本地运行数据以及用户尚未提交的工作。

## 非目标

- 不新增或修改 Python、前端及构建工具的实现代码。
- 不引入 mypy、pre-commit、前端框架或新的 CI 工具。
- 不拆分多个目录级 `AGENTS.md`；当前项目规模使用根目录单一规则即可。
- 不要求无关重构，也不把建议性偏好写成无法执行的强制规则。

## 方案选择

采用仓库定制的根目录单文件方案。相比通用 Python 模板，它能够准确引用 EvalHub 的模块边界、
验证命令和文档位置；相比多层规则文件，它更容易发现、理解和维护。

## 文件结构

`AGENTS.md` 使用中文编写，命令、路径和代码标识保持原文。内容按以下顺序组织：

1. 适用范围和规则优先级。
2. 项目事实与常用命令。
3. 修改前的检查要求。
4. Python 代码规范。
5. 架构和模块边界。
6. 测试与缺陷修复要求。
7. 前端、脚本、配置和文档约束。
8. 安全、依赖与兼容性要求。
9. 完成定义和交付说明。

## 核心约束

### Python 质量

- 以 Python 3.11 为最低运行版本，遵循 `pyproject.toml` 中 Ruff 的 100 字符行宽和既有规则集。
- 新增或修改的公共函数、方法和数据结构提供准确类型标注；避免无意义的 `Any`。
- 函数和模块保持单一职责，优先复用现有抽象，避免重复逻辑和无关重构。
- 异常处理必须保留上下文，不允许静默吞掉异常或使用无说明的宽泛捕获。
- 不在领域逻辑中加入网络、文件系统、环境变量或框架细节。
- 本次新增或修改的每个顶层函数、实例方法、类方法、静态方法和异步方法都必须提供详细
  中文 docstring，说明用途、参数、返回值和可能抛出的异常。
- 本次新增或修改的函数或方法体按有效代码行计数；空行、注释和 docstring 不计数，任意连续有效
  代码不得超过 5 行而没有详细中文注释。
- 高频中文注释必须解释目的、业务含义、约束或原因，并放在完整表达式和逻辑块边界；不得用
  无信息注释充数，也不得拆开装饰器、函数签名、多行表达式或字符串。
- 注释密度要求只覆盖本次新增或修改的 Python 代码，不要求补写未触及的旧代码。

### 架构边界

- `domain` 保存实体、枚举和抽象接口，不依赖具体适配器、API 或基础设施。
- `engine` 编排评测流程，依赖领域抽象而非具体实现。
- `adapters`、`registry` 和 `datasets` 负责外部系统、持久化或数据加载边界。
- `api`、CLI、`server.py` 和 `run_evalhub.py` 作为入口层，负责输入转换和依赖装配。
- 新 evaluator 或 adapter 应遵循现有基类、协议和注册机制，不绕过扩展点。

### 测试与验证

- 新功能必须覆盖正常路径和关键边界；缺陷修复必须先用回归测试复现问题。
- 测试应确定、隔离且快速，不依赖真实网络、外部模型服务、执行顺序或残留本地状态。
- 完成修改前至少运行：

  ```bash
  .venv/bin/python -m ruff check .
  .venv/bin/python -m pytest
  ```

- 若修改范围需要额外验证，应先执行针对性测试，再执行完整检查；无法执行时必须说明原因和风险。

### 仓库级约束

- 原生前端沿用现有 HTML、CSS 和 JavaScript，不擅自引入框架、打包器或依赖管理器。
- 新依赖、公共接口、配置格式和持久化结构变更必须有明确必要性，并同步更新配置与文档。
- 运行方式、API、架构、数据模型、Ollama 集成或阶段计划变化时，更新 `docs/` 中对应文档。
- 不提交密钥、`.env`、本地数据集、模型产物、运行日志、报告或缓存。
- 不覆盖、回退或整理用户的未提交修改；只编辑任务范围内文件。

## 完成标准

- 根目录存在一个 `AGENTS.md`，且不创建目录级同名规则文件。
- 文件内容与 `pyproject.toml`、README、现有目录结构和文档流程一致。
- 所有命令和路径均可在当前仓库中解析，不包含临时标记或不存在的强制工具。
- 中文注释规则明确方法范围、有效代码行计数、5 行上限、内容质量和旧代码豁免。
- 最终交付说明列出修改文件、实际验证命令、验证结果及仍存在的风险。
