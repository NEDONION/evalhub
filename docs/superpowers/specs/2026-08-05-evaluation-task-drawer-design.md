# 评测任务详情 Drawer 设计

## 目标

任务列表保持在页面主区域。用户选择任务后，详情从右侧 Drawer 打开并独立滚动，不再位于全部任务之后。

## 交互与布局

- 点击任务行或切换任务类型时打开对应任务详情。
- 桌面 Drawer 最大宽度为 840px；移动端占满可用宽度和高度。
- Drawer 使用浏览器原生 `<dialog>`，支持关闭按钮、遮罩和 `Esc`，关闭后仍保留任务选择。
- Drawer 顶部关闭栏固定，任务进度、资源、节点、结果和失败样例在其下方独立滚动。
- 任务详情尚未返回时在 Drawer 内显示加载状态，不能短暂展示上一任务详情。

## 边界

- 复用现有 `TaskDetail`、任务轮询、取消和节点重试逻辑。
- 不修改 API、任务模型、路由或持久化结构。
- 不引入 Drawer、焦点管理或动画依赖。

## 验证

- 组件测试覆盖任务点击打开、关闭按钮关闭、详情不再位于普通页面流中。
- 保留类型筛选、FIFO 排队位置和旧任务兼容测试。
- 通过完整前端测试、类型检查、生产构建及仓库级检查。
