# 本地答题模型目录扩充设计

## 目标

扩充“模型评测”下拉框中的本地 Ollama 候选，让用户可以比较多个至少 3B 参数的
通用、推理和代码模型。新增模型不得出现在 Agent 评测下拉框中，也不得依赖登录、
API Key 或云端推理。

## 模型范围

新增以下推荐项，统一设置 `evaluation_types: ["model"]`：

| Ollama 标签 | 预估大小 | 定位 |
| --- | ---: | --- |
| `qwen2.5:3b` | 约 1.9 GB | 轻量中文与通用答题 |
| `qwen2.5:7b` | 约 4.7 GB | 均衡中文与通用答题 |
| `qwen3.5:4b` | 约 3.4 GB | 新一代紧凑多模态答题 |
| `qwen3.5:9b` | 约 6.6 GB | 新一代高质量通用答题 |
| `llama3.2:3b` | 约 2.0 GB | 英文、摘要与指令跟随对照 |
| `phi4-mini:3.8b` | 约 2.5 GB | 数学、逻辑与轻量推理 |
| `gemma3:4b` | 约 3.3 GB | Google 本地通用答题 |
| `gemma3:12b` | 约 8.1 GB | Google 中型高质量答题 |
| `deepseek-r1:8b` | 约 5.2 GB | 数学、代码与长链推理 |

现有目录和已安装模型保持可见。Kimi K2.5、Gemini 以及其他 `:cloud` 模型不加入，
因为它们不满足纯本地运行约束。

## 实现

仅扩充 `RECOMMENDED_OLLAMA_MODELS`，沿用现有 API、用途过滤、容量展示、下载按钮和
自定义下拉框。无需新增前端状态或组件。同步更新目录测试和本地模型指南。

## 验证

- 目录测试断言九个新增标签存在、顺序稳定且只支持 `model`。
- 相关 Ollama 状态测试、完整 pytest、Ruff 和 `git diff --check` 通过。
- 不执行模型下载或真实推理，避免测试依赖网络和本地 Ollama 状态。
