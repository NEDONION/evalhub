# EvalHub 蓝白 Vercel 风格控制台重设计

## 目标

把 EvalHub 当前的本地评测页面重构为蓝白色系、克制紧凑的单页控制台。页面借鉴 Vercel 产品界面的信息密度、边框体系和操作层级，但使用蓝色作为品牌与主操作强调色。

设计必须忠实反映当前产品能力：只为已有功能提供入口，不展示没有路由、页面或后端能力的占位目录。

## 设计原则

- 蓝白色系：浅蓝灰页面背景、白色内容面、深蓝黑正文、清爽科技蓝主操作。
- 克制层级：主要依靠留白、1px 边框、字重和少量底色建立层级，不使用厚重阴影或大面积渐变。
- 真实入口：删除模型注册、Benchmark、任务、报告、排行榜和发布门禁等无功能导航。
- 操作聚焦：页面首要任务是确认本地环境状态、选择数据集与模型、配置样本范围并发起评测。
- 就地反馈：加载、错误、未准备和执行结果显示在其所属模块中，不把所有反馈都塞入原始 JSON。
- 渐进披露：先展示人类可读的评测摘要，原始 JSON 默认折叠，供排查时展开。

## 视觉系统

### 色彩

- 页面背景：`#F7F9FC`
- 内容面：`#FFFFFF`
- 主色：`#2563EB`
- 主色悬停：`#1D4ED8`
- 主文字：`#0F172A`
- 次要文字：`#64748B`
- 边框：`#E2E8F0`
- 柔和强调背景：`#EFF6FF`
- 成功、警告和错误色只用于状态圆点、标签、提示条和对应文字，不作为大面积装饰色。

### 形态与排版

- 使用系统无衬线字体栈，避免运行时加载外部字体并保证中文可读性。
- 内容卡片采用 6–8px 小圆角、1px 浅色边框和极弱阴影。
- 主按钮使用蓝底白字，次按钮使用白底深色文字和浅色边框。
- 标题、说明和辅助信息形成稳定的三级字号与字重层级。
- 控件高度、间距和状态卡密度保持紧凑，避免传统企业后台的大块蓝色导航和松散卡片阵列。

## 页面结构

### 1. 顶部栏

顶部栏是唯一的全局导航区域，包含：

- EvalHub 品牌标识和“本地评测控制台”说明。
- “本地环境”标识。
- EvalHub 服务状态。
- 刷新状态按钮。

页面不保留永久侧边栏，也不展示不可用的导航项。

### 2. 环境概览

使用一组紧凑状态单元展示：

- EvalHub 服务状态。
- Ollama 状态。
- 数据集总数与已缓存数量。
- 最近一次评测得分。

状态单元是信息摘要，不重复堆叠同等权重的大卡片。

### 3. 本地推理环境

集中展示 Ollama 命令、服务地址、当前模型、本地模型数量及可操作提示。未安装、未启动、缺少模型和已就绪使用不同的状态标签与就地说明。

### 4. 核心评测工作区

桌面端采用左右双栏，窄屏改为单栏：

- 左栏：数据集、MMLU 学科、适配器、模型和 Ollama 地址。
- 右栏：全部样本、快速试跑和自定义数量，以及缓存数据集、发起评测操作。

MMLU 学科字段只在选择 MMLU 时显示；自定义数量只在选择自定义样本范围时显示。发起评测期间禁用重复提交，并在操作区显示执行状态。

### 5. 数据集资产

数据集使用表格或紧凑列表呈现，列出名称、任务类型、评测指标、样本数、缓存状态和操作。详细描述、本地路径和数据来源作为次级信息，避免每个数据集占用一张大型卡片。

### 6. 评测结果

结果区优先展示：

- 任务状态。
- Benchmark。
- 模型。
- 通过样本数与通过率。
- 平均分。

原始 JSON 默认折叠。没有结果时显示明确空状态；失败时在结果区显示错误提示，同时保留原始错误信息供排查。

## 组件边界

- 顶部栏：品牌、环境与全局刷新。
- 状态概览：从服务、Ollama、数据集和最近结果状态派生摘要。
- Ollama 环境面板：只负责 Ollama 状态和模型可用性。
- 评测配置：收集并验证评测请求参数。
- 数据集列表：展示缓存状态并触发缓存操作。
- 结果摘要：把 API 返回结果转换为人类可读指标。
- 原始输出：仅承担诊断信息展示。

前端重构为独立的 Vite + React + TypeScript 项目，并使用 Tailwind CSS 构建设计令牌和响应式布局。按钮、标签、面板、表单项和提示条采用 shadcn/ui 风格的本地组件，图标使用 Lucide React；不引入大型全量组件库。

组件按职责放置：

- `src/components/ui/`：无业务含义的基础组件与样式变体。
- `src/components/dashboard/`：顶部栏、状态概览、Ollama 面板、评测表单、数据集列表和结果区。
- `src/lib/api.ts`：所有 `/api/*` 请求、响应类型和统一错误转换。
- `src/lib/evaluation.ts`：表单到 API 请求的纯函数映射和展示格式化。
- `src/App.tsx`：页面状态协调和模块组合，不堆积底层视觉细节。

## 数据流与状态

1. React 页面加载或点击刷新时并行请求 `/api/health`、`/api/datasets` 和 `/api/ollama/status`。
2. 数据集响应更新概览和数据集资产区。
3. Ollama 响应更新环境面板、可用模型和评测配置。
4. 缓存操作调用 `/api/datasets/prepare`，完成后刷新数据集状态。
5. 评测表单调用 `/api/evaluations/run`，成功后更新结果摘要、最近得分和原始输出。
6. `sample_mode=all` 不发送 `limit`；`quick` 由后端解释为 5 条；`custom` 发送经过校验的正整数。

开发环境由 Vite 提供热更新，并将 `/api` 代理到本地 Python 服务。生产构建输出到 `frontend/dist`，Python 静态服务器从该目录提供页面和资源。

## 错误与边界情况

- 任一状态接口失败时，只影响所属模块，其余模块仍可显示有效信息。
- Ollama 未安装、服务未启动和模型未下载分别给出准确提示。
- 数据集缓存和评测执行按钮在请求期间进入禁用状态，防止重复请求。
- 自定义样本数量必须是正整数；无效时不提交请求并在字段附近提示。
- 接口错误显示为用户可理解的中文摘要，原始信息保留在诊断区。
- 长模型名、路径和 URL 必须换行或截断，不造成水平滚动。

## 响应式与可访问性

- 桌面端内容设置合理最大宽度并居中，避免超宽屏上信息过度拉伸。
- 在中小屏幕上，概览、评测双栏和结果摘要按优先级折叠为单列或双列。
- 所有表单控件具有可见标签和键盘焦点样式。
- 状态不能只依赖颜色，还必须包含文本。
- 按钮、链接和可展开区域提供清晰的悬停、焦点和禁用状态。

## 验收标准

- 页面不再出现无路由、无内容或无交互的导航入口。
- 整体视觉为蓝白色系，并呈现 Vercel 式克制、紧凑、边框驱动的产品 UI。
- 当前全部接口能力仍可使用：刷新状态、缓存数据集、选择 Ollama 模型和执行评测。
- MMLU 学科与自定义样本数字段按上下文显示。
- 错误在所属模块就地呈现，评测摘要优先于原始 JSON。
- 适配常见桌面宽度和窄屏，不出现水平溢出。
- React 组件测试与表单交互测试通过。
- TypeScript 类型检查通过。
- Vite 生产构建通过，并生成 `frontend/dist`。
- 后端测试保持通过。
- 使用真实浏览器验证加载、状态刷新、表单切换、数据集缓存、评测提交和结果折叠交互。

## 非目标

- 不实现当前后端不支持的模型注册、任务历史、报告中心、排行榜或发布门禁。
- 不新增前端路由；当前仍是单页评测控制台。
- 不更改现有 API 契约或评测引擎。
- 不使用需要运行时联网加载的字体、图标或 UI 资源；Lucide 图标随生产构建一起打包。
