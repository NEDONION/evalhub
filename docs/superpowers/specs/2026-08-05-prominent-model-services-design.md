# 显著模型服务配置入口设计

## 背景与目标

当前 API 服务商配置仅在“发起评测”页面选择支持远程 API 的 Benchmark，且再选择
“API 服务”适配器后出现。这个入口依赖较多前置操作，用户无法在开始评测前直观确认
服务商、默认模型和连接状态。

本次改动采用独立一级页面方案：用户先在“模型服务”页面完成服务商、API Key、模型和
连通性配置，再在评测页面直接复用默认组合。目标是让首次配置明显、重复评测简洁，并
保持现有凭据加密和模型调用边界不变。

## 信息架构

- 侧边栏在“概览”之后新增一级入口“模型服务”，描述为“服务商与默认模型”。
- 入口显示“未配置”或“已配置”状态，状态由选中服务商是否有密钥及默认模型是否非空决定。
- 概览页在既有评测工作流之前增加模型服务状态条，提供“配置模型服务”或“修改配置”动作。
- “发起评测”保留“API 服务”适配器；选中后只展示默认服务商与模型摘要，以及前往独立
  配置页的入口，不再重复展示完整凭据表单。

## 模型服务页面

页面沿用现有蓝白工作台视觉体系，配置表单默认展开，不再要求先点击“管理服务商”。
界面按真实操作顺序组织：

1. 选择 DeepSeek、硅基流动、Kimi 或自定义 OpenAI-compatible 服务商。
2. 确认 Base URL，录入或保留加密 API Key。
3. 选择或手填模型 ID。
4. 点击“保存并测试连接”。

测试成功后显示连接成功、浏览器测得的请求耗时和发现的模型数量，并把 `/models` 返回的
模型 ID 写入原生 `datalist`。探测失败时保留已保存配置和可编辑模型输入，错误信息明确说明
可以继续手填模型 ID。自定义服务商删除、内置服务商重置及 API Key 不回显规则保持不变。

## 状态与数据流

- API Key、Base URL 和服务商公开信息继续使用现有 `/api/model-providers` 接口与 Fernet
  加密 SQLite 仓储；本次不新增凭据接口或数据库字段。
- 默认组合只包含 `provider_id` 和 `model`，使用浏览器原生 `localStorage` 保存。API Key、
  密文和连接错误不会进入浏览器存储。
- `App` 作为默认组合的唯一状态所有者，把同一组合传给模型服务页面和评测表单。
- 页面加载时读取本地偏好；JSON 损坏、服务商不存在或服务商被删除时回退为未配置状态。
- 切换服务商时清空旧模型，避免把一个厂商的模型 ID 误用于另一个厂商。
- 评测表单构造请求时仍只提交 `provider_id`、模型 ID 和服务端提供的 Base URL 快照，不提交
  API Key。

## 组件边界

- `SidebarNav`：增加 `model-services` 视图和配置状态标签。
- `App`：持有并持久化默认服务商与模型，装配独立页面、概览状态和评测摘要。
- `ModelServicesPanel`：负责独立页面说明、就绪状态和完整 `ProviderSettings` 配置区域。
- `ProviderSettings`：支持受控服务商选择、页面默认展开和测试耗时展示；继续独立处理 CRUD、
  模型发现和密钥清空。
- `OverviewPanel`：增加模型服务状态和快速入口，不负责读取服务商 API。
- `EvaluationForm`：消费默认组合，展示摘要并导航到模型服务页面，不再创建第二套凭据状态。

## 错误、安全与可访问性

- 服务商读取失败时页面显示可恢复错误，Ollama 和其他工作区继续可用。
- 测试连接失败不会清除已经保存的服务商配置或模型文本。
- 密码输入继续使用 `type="password"` 和 `autocomplete="new-password"`，已保存密钥只显示末四位。
- 连通性耗时由浏览器围绕现有测试请求计算，不改变后端响应契约。
- 所有新增控件提供可见标签、键盘焦点和语义化状态文本；状态不仅依赖颜色表达。
- 移动端沿用现有横向导航，模型服务表单在窄屏降为单列。

## 测试与验收

- 侧边栏始终能看到“模型服务”，并根据默认组合显示正确状态。
- 概览页未配置和已配置状态都提供正确入口。
- 模型服务页面初始即显示完整配置表单。
- 保存并测试成功时展示耗时和模型数量；失败时仍能手填模型 ID。
- 切换服务商清空旧模型；刷新后恢复有效默认组合。
- 无效本地存储和已删除服务商回退到未配置状态。
- 发起 API 评测时复用默认 `provider_id` 和模型，且请求与快照不含 API Key。
- 前端测试使用 API mock，不访问真实厂商；完整 Vitest、TypeScript 构建、Python 测试、Ruff
  和 `git diff --check` 在交付前通过。

## 非目标

- 不增加服务端用户账户、跨浏览器偏好同步或多套默认组合。
- 不增加独立健康检查守护进程、周期性探测或厂商特定 SDK。
- 不改变 Agent 仅支持 Ollama 的现有约束。
