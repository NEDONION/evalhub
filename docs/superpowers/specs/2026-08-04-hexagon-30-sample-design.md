# EvalHub Hexagon 30 题协议设计

## 目标

将 `evalhub-hexagon-v1` 从每个能力维度 10 题缩减为 5 题，完整运行从 60 次模型调用降为
30 次，同时保持六维能力覆盖、真实固定来源、中文辅助展示、断点恢复和结果审计。

## 固定题数

| Benchmark 节点 | 能力维度 | 题数 |
| --- | --- | ---: |
| `hexagon-mmlu` | 知识 | 5 |
| `hexagon-ifeval` | 指令遵循 | 5 |
| `hexagon-gsm8k` | 数学 | 5 |
| `hexagon-bbh` | 综合推理 | 5 |
| `hexagon-humaneval` | 代码 | 5 |
| `hexagon-truthfulqa` | 安全可信 | 3 |
| `hexagon-bbq` | 安全可信 | 2 |

安全可信维度合计 5 题。聚合时两个来源继续按样本计数汇总，不再使用各 0.5 的等权重，避免
3 题与 2 题切片被错误视为同等样本量。

## 清单选择

继续使用已核验的 60 题清单作为候选来源，只保留每个来源现有稳定顺序中的前 N 条：前五个
维度各保留 5 条，TruthfulQA 保留 3 条，BBQ 保留 2 条。题目正文、参考答案、来源键、中文翻译
和摘要不重新生成，减少不必要的数据变化。

发布清单仍使用 `hexagon_v1.json`，但协议版本从 `1.0.0` 升为 `1.1.0`，内容、清单 SHA-256、
固定分层集合和期望计数更新为 30 题协议。套件 ID 保持 `evalhub-hexagon-v1`，避免控制台出现
两套近似套件；Hexagon 成员和套件的版本字段同步为 `1.1.0`，行业核心套件版本不变。

## 历史与恢复

- 已完成的 60 题任务和样本记录继续保存在 SQLite 中，不删除、不改写。
- 当前排行榜只接受 `all` 模式、完成数和总数均为 30、且具有协议指纹的任务。
- 旧 60 题成绩不会与新 30 题成绩混排。
- 清单 SHA-256 变化会阻止旧运行中任务继续复用检查点；用户需创建新任务。
- 新任务冻结新的题数、清单摘要、来源 revision、提示版本和生成参数。

## 实现范围

1. 先修改 Registry、清单校验、工作流、API 和成绩过滤测试，使其期望 30 题并确认失败。
2. 将固定清单裁剪为 `[5, 5, 5, 5, 5, 3, 2]`，同步固定分层和 TruthfulQA 选项顺序。
3. 更新 Registry 题数和安全节点权重，使六维聚合按每题等权。
4. 将成绩完整性门槛从 60 改为 30。
5. 同步 README、运行指南、Hexagon 正式设计和故障排查文档中的当前口径。

不增加动态题数配置，不保留可切换的 60 题版本，也不修改行业核心套件。

## 验证

- 固定清单恰好 30 个唯一样本，六个维度各 5 题。
- 七个来源计数恰好为 `[5, 5, 5, 5, 5, 3, 2]`。
- Oracle 完整流程持久化 30 条样本并生成六维满分能力图。
- API 报告套件总样本数 30。
- 29 题和旧 60 题任务均不进入当前 Hexagon 排行榜。
- 相关测试先红后绿，最后运行全量 pytest、Ruff、前端构建和 Markdown 链接检查。
