# EvalHub 本地端口安全重启设计

## 背景

`scripts/start_local.sh` 直接在 `EVALHUB_PORT`（默认 `8000`）启动服务。如果上一次 EvalHub 仍在监听该端口，Python 会在绑定端口时抛出 `OSError: [Errno 48] Address already in use`。

## 目标

每次执行本地启动脚本时，自动关闭占用目标端口的旧 EvalHub，等待端口释放后再启动新实例，同时避免误杀其他服务。

## 行为设计

启动脚本在构建前端和处理 Ollama 之后、启动新 EvalHub 之前执行端口检查：

1. 使用 `lsof` 查询目标 TCP 端口上的监听进程。
2. 如果端口空闲，直接继续启动。
3. 如果端口被占用，请求 `http://<host>:<port>/api/health`，并确认响应中的 `service` 为 `evalhub`。
4. 确认是旧 EvalHub 后，对监听进程发送 `SIGTERM`，最多等待 5 秒让端口释放。
5. 如果端口仍未释放，启动失败并输出 PID 与人工处理提示；不自动升级为 `SIGKILL`。
6. 如果健康接口不能确认占用者是 EvalHub，启动失败并输出占用 PID；不终止未知进程。

`EVALHUB_HOST=0.0.0.0` 时，健康检查使用 `127.0.0.1`，监听地址仍保持用户配置。

## 组件边界

- `scripts/stop_existing_evalhub.py`：负责查询监听 PID、验证健康接口、发送终止信号并等待端口释放。
- `scripts/start_local.sh`：保持启动编排职责，只调用安全清理脚本后再启动服务。

清理脚本只使用 Python 标准库和系统已有的 `lsof`，不引入运行时依赖。

## 错误处理

- 未安装 `lsof`：明确报错并停止，不在无法识别占用者时继续。
- 未知服务占用端口：明确报错并停止，不杀进程。
- 旧 EvalHub 未在 5 秒内退出：明确报错并停止，不强制杀死。
- 端口已经空闲：幂等成功。

## 测试策略

使用 Python `unittest` 覆盖以下行为：

- 空闲端口直接成功。
- 健康接口确认旧 EvalHub 后终止监听进程，并观察端口释放。
- 非 EvalHub 服务占用端口时拒绝终止。
- `0.0.0.0` 转换为本地健康检查地址。
- 启动脚本在启动服务前调用安全清理脚本。

测试先失败，再实现最小代码使其通过，最后运行启动脚本语法检查、Python 全量测试和一次真实端口冲突回归。
