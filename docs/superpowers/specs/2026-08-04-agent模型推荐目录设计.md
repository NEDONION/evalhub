# Agent 模型推荐目录设计

## 目标

把 Ollama 推荐目录替换为五个不超过 5 GB、适合固定 Codex CLI 壳的本地模型。已安装但不在
推荐目录中的模型继续由现有合并逻辑保留，避免隐藏用户资产。

## 模型目录

| Ollama 标签 | 展示名称 | 预估大小 | 定位 |
| --- | --- | ---: | --- |
| `granite4.1:3b` | Granite 4.1 3B | 2.1 GB | 默认平衡档，支持编码、工具调用和结构化输出 |
| `qwen2.5-coder:7b` | Qwen2.5 Coder 7B | 4.7 GB | 代码专项能力档 |
| `granite3.3:8b` | Granite 3.3 8B | 4.9 GB | 非 Qwen 高能力档，支持代码与函数调用 |
| `phi4-mini:3.8b` | Phi-4 Mini 3.8B | 2.5 GB | 推理与函数调用对照档 |
| `llama3.2:3b` | Llama 3.2 3B | 2.0 GB | 轻量通用 Agent 对照档 |

首次默认模型改为 `granite4.1:3b`，前端、服务端和 CLI 的默认值保持一致。

## 实现

继续复用 `evalhub.ollama.RECOMMENDED_OLLAMA_MODELS` 和现有 `model_options` 响应，不新增接口、
前端分支或依赖。下拉框仍按“已安装模型优先、推荐模型补齐”的顺序渲染；选中未安装模型时，
继续使用现有下载入口和评测阻止逻辑。

## 验证

- 单元测试锁定五个推荐模型的名称、顺序和预估大小。
- 回归测试确认额外已安装模型仍保留并排在推荐模型之前。
- 更新 Ollama 安装指南中的推荐命令和默认示例。
- 运行相关 pytest、完整 pytest、Ruff 和 `git diff --check`。

## 范围外

不下载模型，不按硬件动态筛选，不为模型评测和 Agent 评测建立两套目录，也不修改下拉框布局。
