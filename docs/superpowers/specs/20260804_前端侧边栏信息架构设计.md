# 前端侧边栏信息架构设计

## 目标

当前控制台把运行环境、评测配置、Benchmark 资产和结果详情纵向堆叠在同一页面。新增侧边栏后，每个视图只承载一类任务，同时继续共享下载、评测、表单和刷新状态，避免切换目录后丢失工作进度。

## 页面分区

- **概览**：展示服务、Ollama、数据集和最近得分四项就绪指标，并提供各功能入口。
- **发起评测**：展示评测配置表单。模型未安装时明确阻止 Ollama 评测，并引导到资产管理。
- **资产管理**：集中展示 Ollama 模型状态、模型下载进度以及 Benchmark 数据集缓存/更新操作。
- **评测结果**：展示当前会话最近一次评测的状态、指标和失败样本。

## 导航与布局

桌面端使用固定宽度的左侧目录和右侧内容区；窄屏使用顶部横向可滚动目录。导航通过 React 本地状态切换视图，不新增路由依赖。`App` 仍然拥有模型、地址、当前视图以及 `useEvalHub` 返回的异步状态，因此切换视图不会卸载全局任务状态。

侧边栏使用当前蓝白控制台视觉体系。活动项用蓝色左侧轨道和浅蓝底表达，其他项保持安静。目录项附带简短说明，承担信息架构作用，不添加无意义装饰。

## 组件边界

- `SidebarNav`：只接收当前视图、菜单项状态和切换回调，不访问 API。
- `OverviewPanel`：只展示就绪指标和入口操作，不复制资产或评测表单。
- `App`：根据当前视图组合现有组件；所有数据请求和任务状态仍由 `useEvalHub` 管理。
- `EvaluationForm`：模型缺失时提供“前往资产管理”动作；不直接负责下载。

## 状态与异常

- 下载、取消、数据集更新和评测执行期间允许切换目录；回到对应页面可继续看到状态。
- 当前视图默认是“概览”。
- 评测成功后自动切换到“评测结果”；失败时保留在评测页并展示原有错误。
- 模型缺失不发送评测请求，并给出可操作的资产管理入口。
- 移动端目录可键盘聚焦并横向滚动，当前项使用 `aria-current="page"`。

## 验收与测试

- 首屏只展示概览，不再一次性渲染所有大型面板。
- 四个目录项均可切换到对应标题和内容。
- 从评测页切换到资产管理再返回，模型选择仍然保留。
- 评测成功后自动展示结果视图。
- 桌面/移动布局、键盘焦点、活动项语义和现有前端测试均通过。
