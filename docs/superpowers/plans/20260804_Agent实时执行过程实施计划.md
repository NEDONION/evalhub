# Agent 实时执行过程 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 Agent 评测任务中实时持久化并展示题目、Codex 外部动作、工具调用、文件变化、隐藏校验和可解释失败分类。

**Architecture:** Codex Runner 以 `Popen` 流式读取 JSONL，通过可选回调把标准化事件送入现有跨进程队列。Agent 任务创建一个轻量 `agent_benchmark` 节点，任务服务把事件追加到现有 `evaluation_node_events`，React 每秒读取节点详情并渲染时间线；不新增数据库表、长连接或第三方依赖。

**Tech Stack:** Python 3.11、标准库 subprocess/threading/queue、SQLite、pytest、React 19、TypeScript、Tailwind CSS、Vitest、Testing Library。

## Global Constraints

- Agent MVP 只支持 `codex + ollama + coding_mini`。
- 只展示外部可观察事件，不保存或展示模型内部思维链。
- 不新增 Python、前端第三方依赖、数据库表、SSE 或 WebSocket。
- Agent 消息最多 1,000 字符，命令与工具输出最多 2,000 字符。
- 未识别 Codex JSONL 事件只计数，不持久化原始正文。
- 旧 Agent 任务、普通模型评测、同步接口和既有结果 JSON 保持兼容。
- 所有 Python 新增或修改函数提供详细中文 docstring 和必要中文逻辑注释。
- 所有 TypeScript 新增或修改函数及回调提供详细中文注释。
- 每个生产行为先写失败测试并确认 RED，再做最小实现。

## File Structure

- `src/evalhub/agent/codex.py`：流式启动 Codex、标准化 JSONL、报告工具调用计数。
- `src/evalhub/benchmarks/coding_mini.py`：生成样本阶段事件、检查文件变化、分类结果。
- `src/evalhub/tasks/executor.py`：把 Trace 事件穿过子进程队列。
- `src/evalhub/tasks/workflow.py`：定义单节点 Agent 审计工作流。
- `src/evalhub/tasks/repository.py`：向现有节点事件表追加运行事件。
- `src/evalhub/tasks/service.py`：维护 Agent 节点生命周期并持久化事件。
- `src/evalhub/tasks/presentation.py`、`src/evalhub/server.py`：继续复用现有节点详情 API，无新增路由。
- `frontend/src/components/dashboard/AgentExecutionTimeline.tsx`：实时 Agent 过程时间线。
- `frontend/src/components/dashboard/EvaluationTaskPanel.tsx`：在 Agent 任务详情中装配时间线。
- `frontend/src/types.ts`：增加 Trace 和样本诊断类型。

- [ ] **Step 3: 实现最小流式 Runner**

版本探测继续使用现有 `run_command`。实际执行使用 `process_factory` 创建 `Popen`，两个 daemon
线程读取 stdout/stderr 并写入标准库 `Queue`；主线程每 0.1 秒检查截止时间和进程状态。

- 超时调用 `terminate()`，等待后仍未退出再调用 `kill()`。
- 非零退出使用安全截断 stderr 生成 `CodexAgentError`。
- 缺少最终消息继续生成现有错误，不伪造成功。
