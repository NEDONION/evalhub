# EvalHub 前端 Agent 工程规范

## 适用范围与优先级

- 本文件适用于 `frontend/` 目录及其全部子目录。
- 本文件继承仓库根目录 `AGENTS.md`；前端规则冲突时以本文件为准。
- 根规范中“前端使用原生 HTML、CSS 和 JavaScript”的描述已经过时。本项目当前使用
  Vite、React、TypeScript 和 Tailwind CSS。
- 只修改当前任务需要的文件，不顺手重构、格式化或整理无关代码。
- `node_modules/`、`dist/`、TypeScript 构建缓存和其他生成产物不得手工修改或提交。

## 项目事实

- 前端使用 React 19、TypeScript、Vite 和 Tailwind CSS，具体版本以 `package.json` 为准。
- 应用源码位于 `src/`，入口为 `src/main.tsx`，顶层页面组件为 `src/App.tsx`。
- 单元与组件测试使用 Vitest、Testing Library 和 jsdom。
- API 请求统一封装在 `src/lib/api.ts`，共享请求与响应类型统一放在 `src/types.ts`。
- 本项目没有服务端渲染；浏览器运行时 API 不得在模块导入阶段产生外部副作用。

## 常用命令

```bash
# 仅在依赖尚未安装或 package-lock.json 变化时安装依赖
npm --prefix frontend install

# 启动开发服务器
npm --prefix frontend run dev

# 运行全部前端测试
npm --prefix frontend run test:run

# 执行 TypeScript 类型检查
npm --prefix frontend run typecheck

# 执行生产构建
npm --prefix frontend run build
```

- 优先从仓库根目录使用 `npm --prefix frontend ...`，确保命令作用于正确项目。
- 先运行与改动最相关的测试，再运行全部测试、类型检查和生产构建。
- 单元测试不得依赖真实网络、Python API、Ollama 服务、墙上时钟或残留浏览器状态。

## 修改前要求

- 先阅读 `package.json`、相关组件或模块、现有测试和调用方，沿用现有模式。
- 先运行 `git status --short`，识别并保护用户已有的未提交修改。
- 修改函数前先使用 `rg` 查找全部调用方；修复应落在所有调用方共享的根因位置。
- 修复缺陷时先添加稳定复现问题的回归测试，再修改实现。
- 行为不明确时优先从现有测试、公开 Props、API 类型和产品文档中获取证据。

## TypeScript 代码规范

### 类型与接口

- 保持 `strict`、`noUncheckedIndexedAccess`、`noUnusedLocals` 和 `noUnusedParameters` 通过。
- 新增或修改的函数、组件 Props、Hook 返回值和公开数据结构必须具有准确类型。
- 优先使用 `unknown` 并在边界处收窄；禁止用无意义的 `any`、类型断言或非空断言绕过检查。
- API 字段沿用服务端 JSON 命名；只在明确的转换边界映射 snake_case 与 camelCase。
- 领域状态优先使用字符串字面量联合类型，不为固定集合重复创建枚举或映射层。
- 只在多个模块共享时导出类型；组件私有 Props 和辅助类型保留在同一文件。

### 结构与可读性

- 使用清晰的领域命名，不使用无信息量缩写、布尔参数堆叠或散落的魔法值。
- 一个函数只承担一个清晰职责；复杂分支拆成可独立测试的小函数，但不为单次调用制造抽象。
- 优先复用已有组件、Hook、类型和工具函数，不复制相同渲染或请求逻辑。
- 模块导入时不得发起请求、写入存储、注册计时器或访问不存在的 DOM 节点。
- 导入顺序保持为第三方模块、空行、仓库内部模块；纯类型导入使用 `import type`。
- 保持现有格式与行宽，避免仅为格式产生大面积 diff。

### 中文注释强制规则

- 本规则只约束本次新增或修改的 TypeScript 与 TSX，不要求为未触及的旧代码批量补注释。
- 每个新增或修改的顶层命名函数、React 函数组件、自定义 Hook、类构造器、实例方法、静态方法和
  异步方法都必须提供详细中文 JSDoc。
- JSDoc 必须说明用途和业务语义，并按实际情况说明参数、返回值、副作用、异步行为以及可能抛出
  的异常；React 组件还应说明关键 Props 和主要渲染状态。
- 简单的内联事件处理、数组映射、状态更新和测试回调不要求逐个添加 JSDoc；当回调包含多步业务
  逻辑、条件分支或非显然约束时，应在完整逻辑块前添加中文说明。
- 函数体不按固定行数机械插入注释。只在复杂分支、异步流程、状态同步、数据转换、兼容处理和
  非显然约束处添加详细中文注释。
- 中文注释必须解释目的、业务含义、约束或原因，不得只复述代码，也不得使用“执行下面代码”
  “处理数据”“渲染组件”等无信息文字。
- 注释放在完整表达式和逻辑块边界，不得拆开函数签名、泛型、多行表达式、链式调用、Props 列表
  或 JSX 标签；清晰的声明式 JSX、类型字段、静态常量和一目了然的代码无需注释。
- 如果一个方法需要大量行内注释才能理解，应先拆分职责或提取有领域含义的命名函数，再保留少量
  关键注释；不要用注释掩盖过长或混杂的实现。

## React 规范

- 使用函数组件和 Hook，不新增类组件。
- Hook 只能在组件或自定义 Hook 顶层调用，依赖数组必须完整且能说明状态同步边界。
- 派生值优先在渲染期间计算；只有计算昂贵或需要稳定引用时才使用 `useMemo`、`useCallback`。
- 避免重复状态；能由 Props 或其他状态推导的值不得再保存一份。
- 异步 Effect 必须处理卸载、竞态或轮询清理；计时器和订阅必须返回清理函数。
- 列表使用稳定的领域标识作为 `key`，不得以数组下标代替已有唯一标识。
- 事件处理器保持职责单一；提交前校验输入，并显式呈现加载、错误、空状态和成功状态。
- 不为简单状态引入全局状态库；跨组件状态优先提升到最近的共同父组件或封装为现有 Hook。

## 可访问性与样式

- 优先使用语义化 HTML；只有原生语义不足时才添加 ARIA 属性。
- 表单控件必须有可关联标签，错误信息应能被辅助技术识别，图标按钮必须有可访问名称。
- 交互必须支持键盘操作，焦点样式不得被移除；状态不能只依靠颜色表达。
- 装饰图标使用 `aria-hidden="true"`，动态状态使用适当的 `aria-live`、`role` 或原生元素。
- 沿用现有 Tailwind 和 `src/styles.css` 约定，不引入新的 CSS 框架、CSS-in-JS 或组件库。
- 响应式布局至少覆盖现有移动端、平板和桌面断点，不硬编码只能在单一屏幕工作的尺寸。

## API、异常与浏览器边界

- 所有 HTTP 调用集中在 `src/lib/api.ts`，组件和 Hook 不直接拼装重复请求逻辑。
- 查询参数使用 `URLSearchParams`，路径参数使用 `encodeURIComponent`，请求体使用明确类型。
- 非成功响应转换为可诊断的 `ApiError`；不得静默吞掉错误或向界面泄露密钥、堆栈和敏感响应。
- 捕获值使用 `unknown` 并可靠收窄；用户界面展示稳定中文信息，详细诊断保留在安全边界。
- 浏览器存储只保存非敏感、确有持久化需求的数据；密钥和令牌不得写入源码或本地存储。
- 环境变量必须使用 Vite 公开前缀并集中在入口边界读取，示例值只能使用虚拟内容。

## 测试规范

- 新功能测试正常路径和关键边界；缺陷修复必须包含修复前失败、修复后通过的回归测试。
- 测试名称描述用户可观察行为，不绑定组件内部状态、Hook 调用次数或实现细节。
- 组件测试优先使用语义角色、可访问名称和用户事件，避免以 CSS 类名或 DOM 层级定位元素。
- API 边界使用 Vitest mock 或轻量 fake；每个测试后恢复全局 fetch、计时器和 DOM 状态。
- 轮询、延迟和时间相关测试使用 fake timers 或受控返回值，不真实等待。
- 不删除断言、放宽业务条件、跳过失败测试或更新快照来掩盖行为回归。

## 依赖、文档与兼容性

- 不因便利增加依赖；先使用浏览器平台、React、TypeScript 和现有依赖提供的能力。
- 确需新增依赖时说明理由，更新 `package.json` 与 `package-lock.json`，并同步运行文档。
- 保持现有组件 Props、导出符号、API 请求格式和用户可见行为向后兼容。
- API 结构变化时同步更新 `src/types.ts`、请求封装、组件、测试和根规范指定的 API 文档。
- 启动、构建或验证方式变化时更新 `frontend/README.md` 及对应根级运行文档。

## 安全与仓库卫生

- 不读取、输出或提交真实密钥、令牌、`.env` 内容和敏感模型响应。
- 不提交 `node_modules/`、`dist/`、测试覆盖率、浏览器截图、缓存和临时产物。
- 不覆盖、回退、暂存或提交用户的无关修改；只对当前任务文件执行精确操作。
- 禁止使用破坏性 Git 或文件命令清理工作区；遇到冲突或不明修改时停止并说明。

## 完成定义

交付前必须确认：

1. 改动范围与请求一致，没有无关重构、依赖或生成文件。
2. 新增或修改的方法具有详细中文 JSDoc，复杂逻辑具有必要且不过量的中文说明。
3. `npm --prefix frontend run test:run` 通过。
4. `npm --prefix frontend run typecheck` 通过。
5. `npm --prefix frontend run build` 通过。
6. 根级 `AGENTS.md` 要求的 Ruff、pytest 和 `git diff --check` 通过。

若某项检查因环境或外部依赖无法执行，必须列出命令、原因和剩余风险，不得宣称全部通过。
